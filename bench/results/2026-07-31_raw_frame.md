# libSQL wide raw frame — 2026-07-31

Session 5 replaces the eager libSQL adapter's 12,000-row raw transport with one
public `timeless_raw_frame` row. Exact `query/4` remains on the selective
per-series path, and `timeless_raw_batches` remains available to direct SQL
users.

The extension's `TRF1` envelope contains series IDs, per-series point counts,
timestamps, and IEEE-754 value bits as checked little-endian columns. The NIF
validates that envelope, reuses immutable label maps from the ETS catalog, and
constructs the final `%{labels: ..., points: ...}` series maps directly. This
removes the intermediate decoded series list that caused nonlinear BEAM GC.

## Reproduction

```sh
MIX_ENV=test mix run --no-compile bench/engine_query_bench.exs \
  --engine libsql --runs 10
```

The local NIF and extension must be rebuilt after Mix compilation because the
precompiler restores its cached native artifacts:

```sh
make -B priv/native/tms_engine.so priv/native/timeless_sqlite_ext.so
```

Environment: Linux 7.1.3 x86-64, Intel Core Ultra 9 185H, `powersave`
governor, 22 BEAM schedulers, Elixir 1.20.2, OTP 29, SQLite 3.53.2. Dataset:
12,000 series x 60 persisted points = 720,000 points.

## Exit-gate result

| Shape | Session 5 start | Final median / p95 | Change |
|---|---:|---:|---:|
| Exact raw, 60 points | 0.348 ms | 0.283 / 0.408 ms | 18.7% faster |
| Narrow raw, 188 series | 3.632 ms | 1.978 / 2.209 ms | 45.5% faster |
| Wide raw, 12K series | 344.221 ms | 113.142 / 113.881 ms | 3.04x faster |

The original Session 0 wide baseline was 372.787ms, making the cumulative
improvement 3.29x. The public <=120ms gate passes at both median and p95, and
the <=5% exact/narrow regression gate passes with both paths faster.

## Final-path attribution

| Stage | Median | p95 |
|---|---:|---:|
| One-row frame fetch | 77.696 ms | 82.906 ms |
| Cached-label lookup | 4.346 ms | 5.116 ms |
| Direct final-map decode | 12.722 ms | 44.490 ms |
| Fetch + labels + final decode | 112.360 ms | 116.105 ms |
| Public `query_multi/4` | 113.142 ms | 113.881 ms |

For comparison, the retained per-series projected path measured 110.249ms for
fetch alone and 178.544ms combined. The direct SQLite benchmark measured the
one-row frame at 63.636ms versus 74.416ms for per-series batch rows.

## Memory and semantics

The wide result serializes to 12,959,022 bytes. A fresh worker sampled at 1ms
intervals peaked 120,596,408 bytes above its baseline, or 9.306x. The benchmark
now enforces a 10x maximum. This includes the 11,664,016-byte frame plus the
eager BEAM tuple/list result; a future lazy API would be a separate contract.

Point order within a series remains stable and timestamps/value bits are exact.
The outer multi-series list is explicitly unordered, matching the legacy and
Rust parallel query paths. Complex TimelessMetrics matchers still post-filter
against cached labels; the extension accepts its existing equality subset.

Focused libSQL tests pass, including native frame order/envelope validation.
The paired extension record documents the core and direct-SQL coverage.
